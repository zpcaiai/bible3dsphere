# Long-Term Pattern Safety

Safety order remains: crisis routing, consent and processing preference,
eligibility, rule discovery, optional model inference, evidence validation,
snapshot publication, then Formation Engine context.

`STORE_ONLY`, `EXCLUDE_FROM_TWIN`, deleted, excluded, unconsented, and crisis
ELEVATED/IMMINENT records cannot generate ordinary patterns, embeddings, or
trajectories. During crisis, deep analysis stops and the response routes to
Crisis Care. Pending patterns never enter Formation Engine context.

Every publishable pattern must have scope, lifecycle, supporting evidence,
counterevidence field, review date, user review status, and limitations. Model
hypotheses also require alternative explanations. Missing fields block both the
long-term snapshot and downstream context.

The safety validator rejects fixed-personality claims, automatic idol judgments,
salvation/divine-will verdicts, causal certainty, permanence claims, spiritual
scores, rankings, and cross-user comparisons. Practice frequency is not growth.
The UI always discloses recording bias and gives support and counterevidence
equal visibility.

Sensitive full text is prohibited from events, audits, logs, metric labels,
graph payloads, pattern payloads, model-call logs, notifications, and technical
health. The user can erase only the long-term model or all Formation Twin data.
