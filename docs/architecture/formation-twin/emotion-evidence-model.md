# Emotion Evidence Model

用户结构化输入的证据是生命事件引用，不附加系统置信度。模型候选必须同时包含来源生命事件、加密内容引用、合法的 `start_offset/end_offset`、证据哈希、模型版本、提示词版本和 Schema 版本。

证据表不保存日记或语音正文。正文仅在授权处理期间从 Batch 2 的 AES-256-GCM 内容仓读取；普通数据库字段、事件总线、日志、监控标签和模型运行审计只能保存引用、偏移、哈希与版本元数据。

证据优先级为：用户当前明确报告最高；用户确认的模型候选次之；规则只描述聚合；未确认模型候选永远停留在“可能”区域。缺失字段不是反向证据，未填写情绪不能被写为 `NO_EMOTION`，记录频次也不能表述为实际发生频次。
