# 语音通话的安全与中国环境部署

> 这份文档对"加密""不被监听"做**诚实**说明：哪些能保护、哪些保护不到。
> 涉及弟兄姊妹在敏感环境下的安全，请完整读完再决定怎么用，不要凭一句"已加密"就放心。

## 一、两层加密，分清楚

| 层级 | 保护谁 | 默认 | 谁仍能听到 |
|---|---|---|---|
| **链路加密 (DTLS-SRTP)** | 防网络中间人/运营商/GFW 被动监听 | WebRTC 强制，永远开 | **LiveKit 服务器能解**（SFU 要转发就得解密） |
| **端到端加密 (E2EE)** | 防服务器/服务商/被迫取证 | 需设"加密口令"才开 | 只有持同一口令的参与者；**服务器拿到的是密文** |

- 不设口令：内容在网络上是加密的，但 **LiveKit（及其运营方）理论上能听到**。
- 设了口令（通话里点"设置加密口令"）：开启 **E2EE**，密钥由口令在你本机派生，**绝不上送后端/服务器**。此时即便 LiveKit、你自己的后端、或被强制取证，拿到的也只是密文。

### 口令怎么分发（关键）
口令一旦经过服务器就失去意义。**务必走带外渠道**：当面、纸条、或 Signal 等端到端加密 IM 私下约定。
**不要**把口令发在本应用的邀请码、群消息、微信、邮件里。群内所有人填**同一个口令**才能互通。

## 二、加密**保护不到**的部分（别误判）

1. **元数据**：谁、在什么时间、连了哪个服务器、通话多久、流量多大——这些 E2EE 不隐藏。流量分析仍可推断"这群人此刻在开实时语音"。
2. **可用性/封锁**：LiveKit Cloud 是境外服务，GFW 可能限速或封锁，导致连不上或断断续续。加密不解决"被墙"。
3. **端点安全**：对方手机若被植入、被人肩窥、或有人开了录音/录屏，加密无能为力。参会者本身可转录。
4. **真实身份**：当前参与者身份用的是登录 email。若担心身份关联，考虑改用昵称、且账号不绑实名手机号。

> 结论：E2EE 能可靠保护**通话内容**不被服务器/网络听到；但**无法**让"正在开会"这件事本身隐形，也挡不住被封或端点泄密。请按真实风险权衡是否在高敏场景使用。

## 三、中国环境下的质量 + 连通性

LiveKit Cloud 全球边缘节点对墙内不友好。建议二选一：

### 方案 A：自托管 LiveKit（推荐，可控）
在靠近大陆、连通性好的地区(**香港 / 新加坡 / 东京**)的 VPS 上自建 `livekit-server`：

- 用 **TLS、跑在 443 端口**（`wss://`），外观与普通 HTTPS 一致，更易穿透限制性网络。
- 配 **TURN over TLS / 443**：严格 NAT、4G、企业防火墙下用 443 中转，显著提升接通率。
- 把 `LIVEKIT_URL` 指向你的自托管地址（如 `wss://rtc.yourdomain.com`），令牌签发逻辑不变。
- **不要**在大陆境内用需 ICP 备案/实名的服务器承载——备案本身就是身份与监控入口，与"不被监听"的目标相悖。

最小自托管参考（服务器侧 `livekit.yaml` 要点）：
```yaml
port: 443
rtc:
  tcp_port: 443         # 允许 TCP/443 回退，穿透 UDP 受限网络
  use_external_ip: true
turn:
  enabled: true
  tls_port: 443         # TURN over TLS，伪装成 HTTPS
  domain: rtc.yourdomain.com
keys:
  <你的 LIVEKIT_API_KEY>: <你的 LIVEKIT_API_SECRET>
```
（443 同时给信令/TURN 时需用不同主机名或前置反代分流，按 LiveKit 部署文档配置。）

### 方案 B：继续用 LiveKit Cloud
省事，但墙内连通不稳定、且是境外大服务（流量特征明显）。**务必开 E2EE**，否则内容对该境外服务可见。

### 已内置的弱网优化（前端）
- Opus + **RED 冗余**（丢包下不卡）、**DTX**（静音不发包省带宽）、语音码率上调。
- 浏览器原生回声消除 / 降噪 / 自动增益；可选 Krisp AI 降噪。

## 四、浏览器限制（重要）
**E2EE 依赖浏览器的 Insertable Streams API**。

- ✅ 系统版 Chrome / Edge / 新版 Safari：支持。
- ⚠️ **微信内置浏览器**：很可能**不支持**，此时会自动降级为"仅链路加密"（顶部显示 🔓）。需要 E2EE 时，请用系统浏览器打开（右上角"在浏览器中打开"）。
- 顶部状态条会明确显示 🔒（端到端加密已开）或 🔓（仅链路加密），以此为准。

## 五、给敏感场景的操作建议
1. 通话里先点"设置加密口令"，确认顶部变 🔒 再开始讲。
2. 口令走带外渠道约定，定期更换；人员变动后立即换。
3. 群规模尽量小；用昵称、不用真名。
4. 高敏内容评估是否改用更激进的方案（如完全离线、或 Signal 群通话——它默认 E2EE 且元数据更少）。本应用适合"内容保密、但不掩盖开会事实"的场景。
